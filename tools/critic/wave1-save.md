## Ranked issues (notable on PASS — none blocks the bar)

1. **`season` is persisted but never restored.** `buildSnapshot` writes `season: host.clock.season()` (`snapshot.ts:123`); `doLoad` applies `weather` (`index.ts:85`) but there is no `world.setSeason(save.season)`. Today this is harmless because `GameClock.season()` derives from `gameTime` (`clock.ts:87–93`) which *is* restored, but `WorldService.setSeason()` exists as an override (used by harness scenarios), so a save taken under an overridden season will silently revert on load. — fix: either apply it symmetrically (`if (save.season && world) world.setSeason(save.season as Season)` next to the weather line, plus one assertion in the success-path test) or drop the field from `SaveFile` as redundant. Pick one; do not leave a write-only field.

2. **A deferred autosave survives a `load()` and then overwrites slot 0 with a copy of the loaded save.** `pendingAutosave` (`index.ts:183`) is set by e.g. `quest-advanced` during dialogue; if the player then loads manual slot 3, the first `explore` tick after the load fires the stale request and replaces the previous autosave with a duplicate of slot 3. Not data-losing in the player's sense (the autosave is disposable) but it discards a distinct restore point. — fix: `ctx.events.on('loaded', () => { pendingAutosave = false; })` (or clear it on `state-changed` → `loading`); one-line test in the gating suite.

3. **Encounter-start autosave depends on a contract the combat module has not yet signed.** The `explore→combat` trigger snapshots at the moment the state machine transitions (`index.ts:198–200`). If the future `CombatService.start()` requests `'combat'` *before* `isActive()` returns true, `buildSnapshot` will write a save with no combat block and no error (the throw only fires when `isActive()` is true and `serialize()` is null). — fix: nothing in `src/save`; record in `STATUS.json` / the combat builder brief that `isActive()` and `serialize()` must be valid before `request-state 'combat'` is emitted, and that the wave-2 harness `combat-*` scenario should assert slot 0 carries `combat.encounterId` after the encounter begins.

4. **`doLoad` assumes the `'loading'` transition succeeded.** It emits `request-state 'loading'` and later reads `host.state.prev` on early failure (`index.ts:61, 110`). If a caller invokes `load()` from a state where `loading` is illegal (`dialogue`, `combat` per `state.ts`), the machine stays put, `prev` is a stale earlier state, and the failure path requests a spurious transition (e.g. `dialogue → explore`, which *is* legal and would kill the dialogue). Unreachable via F9 (gated) and via the pause menu (`paused → loading` is legal); reachable only by a future UI calling `save.load()` from an unexpected state. — fix: after the emit, `if (host.state.state !== 'loading') throw new Error('Cannot load from this state')` before touching storage, and route that through the existing catch with `worldTouched === false` (which then requests `prev` — acceptable because nothing changed) or simply `return` after the toast.

5. **`existingCreatedAt` now pulls every row's bytes from IndexedDB to read one string.** `store.list()` → `getAll()` deserialises all slots including their `Uint8Array` blobs (`db.ts:92–99`) on every `save()`. Correctness is fine and it *is* cheaper than the round-1 gunzip for a single slot, but with 7 populated slots at up to 2 MB each this is the wrong shape. — fix: add `getMeta(slot): Promise<SaveMeta | null>` to `SaveStore` (IDB: `get(slot)` and return `.meta`; the others are trivial) and use it here; also lets the UI's save list avoid loading blobs if `list()` is later changed to use a meta-only index.

6. **Timing-based waits in the `register()` tests.** The four gating tests use `flush(20)` (a 20 ms `setTimeout`) to let the fire-and-forget autosave complete before asserting on `svc.list()`. On a loaded CI runner this is a flake risk. — fix: have `triggerAutosave` record its promise on a module-level `lastAutosave: Promise<void>` (or expose it via a test-only hook) and `await` it instead of sleeping; or assert with `vi.waitFor`.

7. **`fast-travel` hook is untested.** Understandable — `ExplorationService` is a stub — but the wiring at `index.ts:221–227` is lazy (checked once per scheduler tick) and the test suite could register a fake exploration service with a recording `on()` and emit through it, the way `chapter-changed` is tested. — fix: one more case in the gating suite when the exploration module lands.

8. **Loaded `weather` is cast, not validated.** `world.setWeather(save.weather as Weather)` (`index.ts:85`) forwards whatever string is in the file. `assertSaveShape` could check it against the `Weather` union (or `WorldService` should ignore unknown values). Low; only matters for hand-edited imports.

Cross-cutting, for the integrator (unchanged from round 1, not the save module's fault): `World.clear()` does not fire remove-listeners, so modules must treat `state-changed → loading` as "tear down transient scene objects" and `'loaded'` as "rebuild", or old meshes leak across a load.
