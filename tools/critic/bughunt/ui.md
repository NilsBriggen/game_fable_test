# Bug hunt — ui (src/ui)

Probes: `tools/critic/probes/ui/{pause-over-gameover,result-card-over-gameover,hotkeys-leak-under-pause,target-card-stale}.test.ts` (`@vitest-environment jsdom`; run: `npx vitest run --config tools/critic/probes/ui/vitest.config.ts`), all passing (i.e. proving each bug reproduces). jsdom is not a project devDependency — installed ad hoc (`npm install --no-save jsdom`) for these probes only.

| # | Severity | File:line | Repro | Expected vs actual |

| 1 | **blocker** | `combatUi.ts:451-463` | During active combat, open Pause (Escape), then press `1`-`9` or Space; probe: `hotkeys-leak-under-pause.test.ts`. | Expected: a modal over combat owns the keyboard (as `dialogueUi.ts:107`'s `menuOpen()` guard already does for dialogue). | 2 | logic | `index.ts:139` + `index.ts:49-52` | Reach the game-over screen (party wipe), press Escape; probe: `pause-over-gameover.test.ts`. | Expected: Escape is a no-op on the dedicated game-over screen (or closes it), and no menu renders while the state can't legally become `paused` (`gameover` only allows `title`/`loading`, `state.ts:14`). **Checked, not bugs:** dialogue choices are correctly gated (`choicesEl` is only populated in `finishType()`, so nothing is clickable pre-typewriter; `dialogueUi.ts:78-93`); skill-check odds format matches its input (`computeCheckOdds` in `quest/dialogue.ts:45` already returns 0-100, matching `formatCheckOdds`'s `Math.round(pct)`); `#dialogue-root[hidden]{display:none!important}` (`ui.css:144`) correctly beats the ID's own `display:flex`; toasts are capped at 6 (`hud.ts:112`); save-to-autosave is blocked (`menus.ts:481`); flee confirm's Cancel and backdrop-click both resolve `false` and are honored (`hud.ts:167,176`, `combatUi.ts:40`); reaction modal and initiative chips *are* refreshed every `renderAll` (unlike the target card) so they don't go stale; compass bearing math (`helpers.ts:47-52`) is internally consistent and probe-tested (`helpers-edge.test.ts`) at the seam and at cardinal facings; menu-root listener lifecycle (dialogue keydown, combat canvas/keydown) is either add-once-at-register or matched add/remove per `show()` — no leak found.
