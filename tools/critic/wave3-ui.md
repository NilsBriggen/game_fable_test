## Score: 6/10   (pass bar 8)  → FAIL (round 1/3)

The captured screens are genuinely good: every menu is legible at 1080p, the parchment/ink language is consistent from title to combat, nothing overlaps *in the frames the harness took*, all six scenarios report `errors: []`, `warnings: []`. The rubric's 8-bar items — readable screens, map with markers, save/load with thumbnails, hover previews in combat — are all *implemented*. What keeps it at 6 is three player-facing breakages that no harness scenario happens to frame but every real session hits within minutes: **the dialogue panel never actually goes away** (author CSS overrides the `hidden` attribute — confirmed in Chromium), **the combat panels never go away after a fight** (the UI waits for a null state the engine never emits), and **a party wipe soft-locks the game** (no `gameover` screen, Escape ignored). Each is a small fix; together they mean the "no overlapping text" clause fails from the second scene of the prologue onward. Below them sit real but smaller gaps (menu hotkeys firing on the title/creation screens, `[NN%]` without the skill name, unreachable trade/rest menus, inert settings).

## Ranked issues

1. **Dialogue panel never hides — author CSS beats the `hidden` attribute.** `dialogueUi.ts:22,117` toggle `panelRoot.hidden`, but `ui.css:159` sets `#dialogue-root { display:flex }`; an author-origin declaration overrides the UA `[hidden]{display:none}` regardless of specificity. Confirmed in the harness Chromium: computed `display: flex`, 197 px tall, and `elementFromPoint(960,1000)` returns `#dialogue-root`. `hide()` also does not clear the children, so after every conversation the last panel (text + still-clickable choices) stays on screen at z-index 70 — above the HUD prompt and above `#combat-root` (z 40), i.e. over the ability bar and unit card in the very next fight; `#ui > *` gives it `pointer-events:auto`, so it also eats clicks in the bottom band. — evidence: cascade check above; `dialogue-gessler-hat.png` shows the panel geometry that persists. — fix: add `#dialogue-root[hidden] { display:none !important; }` (or switch to the `.hidden` class the other roots use) in `ui.css`, and `clear(panelRoot)` inside `hide()` (`dialogueUi.ts:115-120`).
2. **Combat panels never hide after a fight.** `index.ts:104-112` hides combatUi only when `combat.on('state')` delivers a falsy view; `CombatEvents.state` is `[view: CombatStateView]` and `engine.ts:755-758` only emits when a view exists. After `finish()` the view has `phase:'ended'`: `renderObjectives`/`renderLog` (`combatUi.ts:229,242`) hide only in `deploy`, so the Objectives panel (top:62/left:14) and the Log panel stay on screen in explore, the Objectives panel sitting exactly under the HUD quest tracker (`.hud-quest` top:62/left:20) — overlapping text; the canvas click/mousemove handlers keep running on the stale `lastView`; and the next encounter enters through `update()` instead of `show()`, so `selectedAbility` is not reset. — evidence: code paths cited; `engine.ts:655-657` (`emitState()` then `request-state explore`). — fix: also subscribe `combat.on('end', () => { shown=false; combatUi.hide(); })` or hide when `view.phase==='ended'` and the result panel's Continue is clicked; make `hide()` clear every panel (`combatUi.ts:405-410`).
3. **Game-over soft-lock.** `engine.ts:657` requests `gameover` on a wipe; nothing in `src/ui` handles that state (grep), `showHud` is off, the Escape handler only opens Pause from `explore|combat|dialogue|cutscene` (`index.ts:121-126`) and the only thing on screen is the combat "Defeat" card whose Continue merely clears itself. The player is stuck with a live world and no input. — fix: in the `ctx.state.onChange` block (`index.ts:141-145`) render a game-over panel on `to==='gameover'` (Load / Title, both legal from `gameover` per `state.ts:14`), and include `gameover` in the Escape list.
4. **Menu hotkeys fire on the title and creation screens; dialogue keys fire under a pause menu.** (a) `index.ts:128-132`: `Tab/i/j/m` are gated only by `isTyping()` and `state !== 'combat'`; on `title` they replace the title screen with an "No inventory." modal (state `title` cannot pause, so `openMenu` just clears `#menu-root`), on `creation` they wipe the half-filled form (all `state` in `renderCreation` is local; `closeMenu` re-renders a blank one). (b) `dialogueUi.ts:96-100`: 1-9/Enter/Space are live while the pause modal is over a conversation; a keypress picks a choice, the runner's `finally` requests `explore` (legal from `paused`), and the game resumes *behind* the still-open pause modal. — fix: (a) return unless `['explore','dialogue','cutscene','paused'].includes(ctx.state.state)`; (b) have dialogueUi consult a `menuOpen()` predicate passed from `index.ts` (or `ctx.state.state === 'dialogue'`).
5. **Skill-check odds render as `[65%]`, not `[Speech 65%]`.** `dialogueUi.ts:76` prints `[${Math.round(c.checkOdds)}%]`; `formatCheckOdds` (`helpers.ts:92`) is unused in production; `DialogueNodeView` (`services.ts:406-411`) carries no skill label and `quest/dialogue.ts:183-187` sends no `hint`, which the UI only shows for *disabled* choices anyway (`dialogueUi.ts:75`). BG3's whole point is naming the skill. — fix: quest sets `hint: skillName` (or core adds `checkSkill?: string`), and dialogueUi renders `formatCheckOdds(c.hint ?? 'Check', c.checkOdds)` and shows hints on enabled choices too.
6. **Trade and Rest menus are unreachable.** `renderTrade`/`renderRest` exist (`menus.ts:588-666`) but nothing calls `openMenu('trade'|'rest')`; `exploration/interact.ts:57-71` handles travel/talk/loot only and toasts the prompt for everything else. — fix (exploration owner, note for integrator): route `it.kind==='trade'` → `ui.openMenu('trade',{entity})` and `'rest'` → `ui.openMenu('rest')`.
7. **`dialogue.show` leaks a window keydown listener per node and can leave a promise pending.** `cleanup()` (`dialogueUi.ts:107`) runs only from `pick()`; `hide()` resolves the promise (`dialogueUi.ts:118`) but never removes the handler, and a second `show()` while one is pending overwrites `resolveCurrent` without resolving or cleaning the first. `main.ts:169-179` (the Act-1 auto-player) takes exactly the `void show(); hide()` path, so it accumulates one stale handler per dialogue node, each of which still calls `finishType()`/`renderChoices()` on detached DOM on every 1-9/Enter/Space. — fix: hold `cleanupCurrent` in the closure; call it (and resolve the old promise) at the top of `show()` and inside `hide()`.
8. **Unit card shows no conditions, no defense, no weapon; no enemy inspection.** `CombatantView.status`, `defense`, `weapon` are never rendered (`combatUi.ts:117-172`); Shaken/Prone/Braced/Disarmed only appear as Burden names in the hit line. Hovering an enemy yields a single "Hover X: 63% hit …" line (`combatUi.ts:352`); nothing shows the enemy's HP/defense/status. BG3 puts condition icons on every portrait and a tooltip on every enemy. — fix: add a status chip row and a `Def N · weapon (reach)` line to the card; on enemy hover render a small `cbt-target-card` next to the preview.
9. **No Flee.** `CombatCommand` has `{type:'flee'}` (`services.ts:199`) and the engine reports `fled`; the HUD offers no way to issue it. — fix: a "Flee" button next to End Turn, guarded by a confirm.
10. **Deploy phase hides the objectives** (`combatUi.ts:229`) — the player places troops blind. — fix: show objectives during deploy (they are already in the view).
11. **Settings are inert** — `menus.ts:517-527` writes `ctx.settings`, no module reads it (grep) and nothing persists it to localStorage; the panel promises quality/shadow/render-scale changes that never happen. — fix (world/integrator): consume `ctx.settings` in world's renderer setup and persist in `core/context.ts`; UI should at least save/restore via localStorage.
12. **Currency labels `℔ s d` unexplained.** `helpers.ts:22-25` — period-correct abbreviations, but the brief and LORE §7 name Pfund/Schilling/Pfennig and nothing on screen says which is which. Also `formatPfennig(-0.5)` → `"-0 d"` with a `-0` pfund, and `NaN` leaks into the label (probes). — fix: `title="Pfund / Schilling / Pfennig"` on `.val` and the purse line (or spell out on the purse line), floor before taking the sign, guard non-finite input.
13. **Save/Load polish.** Quicksave slot (6) is read-only for saving but is styled like any other slot and has a Delete button; autosave also deletable; no F5/F9 hint; slot label shows `meta.label` (always "Quicksave"/"Autosave"/user label) but the heading never says "Slot N" for manual saves once they have a label. — fix: `.save-slot.readonly` styling + tooltip, hide Delete on 0/6, add a footer "F5 quicksave · F9 quickload".
14. **Compass renders the S chip twice when facing due south** (`COMPASS_LETTERS` lists S at +180 and −180, `helpers.ts:53`; probe) — doubled text-shadow. — fix: drop the −180 entry and rely on `normalizeAngle`.
15. **Mousemove rebuilds the entire unit card** (`combatUi.ts:355` → `renderUnitCard`) including the `previewAttack` call for the nearest enemy — on a software renderer this is measurable. — fix: update only the `.cbt-preview` node.
16. **Integrator note — `#combat-debug-overlay`**: hidden by `ui.css:13` (`display:none !important`); `src/combat/render.ts:176-194` still installs it under `ctx.harness`. Remove `installDebugOverlay()` once the HUD lands, or the harness keeps paying for a hidden overlay update every state event.
17. **Dead helpers / duplicated logic.** `buildInitiativeChips`, `formatCheckOdds`, `cellToWorldXZ` in `helpers.ts` are only used by tests; `renderInitiative` (`combatUi.ts:101-114`) re-implements the strip and ignores `routed` (a routed unit stays fully lit). Use the helper (it flags routed as down).
18. Small things: creation draws 8 attribute dots of which 4 can fill (`menus.ts:133`); the creation preview's HP/Defense/Morale are UI-side guesses, not `party.derived`; "click / Enter to continue" hint persists after the choices appear; closing Save/Load/Settings opened from Pause resumes play instead of returning to Pause (`index.ts:50-53`).
